# F002 — Rule title too long

**Severity:** warning
**Category:** LLM-friendliness

## What this catches

A rule whose title exceeds **120 characters**. Long titles read more like
prose than directives; they hide the operational core inside elaboration
the model has to parse on every reference.

Example that fires:

```
- title: "Public functions exposed under src/contextos/parsers must have a
   docstring describing every parameter, the return shape, and at least one
   raise clause for the typed errors they can produce; use Google style."
```

(167 characters.)

## Why it matters

A bullet-formatted rule list is most effective when every line is
scannable. Once a title runs past 120 characters, the parser still
captures it, but the human author and the model both lose the pattern of
"one rule = one short line".

Worse, long titles often try to encode rationale or examples inline.
Those belong in the `rationale`, `detail`, `example_good`, and
`example_bad` fields where the analyzer and downstream tools can use
them as structured data.

## Suggested fix

Either split the rule into two, or move the elaboration into structured
fields:

```toml
# Before (F002 fires):
[[rules]]
id = "DOC-001"
title = "Public functions exposed under src/contextos/parsers must have a docstring describing every parameter, the return shape, and at least one raise clause"
severity = "must"

# After:
[[rules]]
id = "DOC-001"
title = "Public functions in src/contextos/parsers/ have a docstring"
severity = "must"
detail = """
The docstring documents every parameter, the return shape, and at least
one raise clause for the typed errors the function can produce.
"""
example_good = '''
def parse_ctx_file(path: Path) -> Document:
    """..."""
'''
```

## Tuning

- Threshold: 120 characters. Constant in
  `src/contextos/analyzers/agent/llm_friendly.py`.
