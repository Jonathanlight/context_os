# X001 — Placeholder marker in rule title

**Severity:** warning
**Category:** Anti-pattern

## What this catches

A rule title containing `TODO`, `FIXME`, `XXX`, or `HACK` as a whole
token (case-insensitive). These markers travel from boilerplate
templates or in-progress edits and rarely belong in a shipped rule.

Examples that fire:

- `TODO: Decide on the timeout policy`
- `FIXME — clean up the validation chain`
- `Use prepared statements (HACK around DB driver bug)`

Examples that **do not** fire:

- `Use TODO-list discipline for branching tasks` — `TODO-list` is a hyphenated word, not a standalone marker.
- `Test the towel function` — substring match would catch `tod` inside `today`; whole-token match doesn't.

## Why it matters

A `TODO` rule reads as "this rule isn't finished yet." The LLM sees an
ambiguous directive surrounded by other (presumably authoritative)
rules; it has to guess whether to apply the rule or skip it. The same
goes for `FIXME` and friends.

## Suggested fix

Either finish the rule and drop the marker, or delete the rule:

| Placeholder | Concrete |
|---|---|
| `TODO: Decide on the timeout policy` | `HTTP clients must use a 5-second connect timeout` |
| `FIXME — clean up validation` | `Validate every request body against the Pydantic schema` |
| `Use prepared statements (HACK around DB driver bug)` | `Use prepared statements for every query` (with `rationale` explaining the driver constraint) |

If the placeholder reflects a real open question, capture it in a
project issue, not in the rule set.
