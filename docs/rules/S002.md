# S002 — Description is too short

**Severity:** warning
**Category:** Skill / description quality

## What this catches

A `SKILL.md` whose `description` is shorter than 50 visible characters
(whitespace runs collapsed before counting). Padding the field with
spaces or newlines does not push it above the floor.

## Why it matters

Descriptions below 50 characters almost always collapse into one of
two failure modes:

- **Capability without trigger** — e.g. `Extracts PDFs.` (15 chars).
  The skill never fires because the model has no trigger signal.
- **Trigger without capability** — e.g. `Use when asked about PDFs.`
  (27 chars). The skill might fire, but the model doesn't know what
  it actually does once it's loaded.

Either way, the description fails its job as routing signal.

## Suggested fix

Expand to one or two sentences. The conventional shape is:

> [What the skill does]. Triggers when [user behaviour].

```yaml
description: |
  Extracts structured invoice data (vendor, total, tax, line items)
  from PDF documents. Triggers when the user uploads a `.pdf` or
  asks to parse / process an invoice.
```

The floor of 50 chars is empirically chosen — there is nothing
operationally meaningful at the boundary, but every description below
it that we surveyed had one of the two failure modes above.

## When to silence

If you have a genuinely terse skill that does one obvious thing on one
obvious trigger, you can suppress S002 in the audit's JSON output and
move on. The warning is calibrated to the median; outliers exist.
