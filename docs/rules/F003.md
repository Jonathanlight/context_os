# F003 — Duplicate rule

**Severity:** warning
**Category:** LLM-friendliness

## What this catches

Two or more rules whose titles normalize to the same string. Titles are
compared after:

- Lowercasing
- Stripping punctuation (`,.;!?` etc.)
- Collapsing internal whitespace to a single space

Examples that fire:

```toml
[[rules]]
id = "STYLE-001"
title = "Use type hints on every public function"
severity = "must"

[[rules]]
id = "STYLE-007"
title = "Use type hints on every public function."   # only difference: trailing period
severity = "should"
```

Both rules collide under normalization; the second one is flagged with a
reference to `STYLE-001`.

## Why it matters

Duplicate rules cost context tokens twice and create silent
disagreement risk. The example above declares the same directive at
both `must` and `should` severity — the model has to pick one, and the
choice is not in the author's control.

Duplicates also distort downstream analyzers. Cross-artifact rules
(XA001) that count how many rules a given file declares about a topic
will over-count.

## Suggested fix

Either delete the duplicate, or merge the two rules:

- If both rules are identical, keep the one with the most metadata
  (rationale, examples) and delete the other.
- If they differ in severity, decide which severity is correct and
  collapse to one rule.
- If they differ in scope (one applies to `src/` and one to `tests/`),
  encode that in `applies_to` rather than declaring two near-duplicate
  rules:

  ```toml
  [[rules]]
  id = "STYLE-001"
  title = "Use type hints on every public function"
  severity = "must"
  applies_to = ["src", "tests"]
  ```

## When to silence

Almost never. If two rules really do mean different things, their
titles should reflect that — at which point F003 won't fire.
