# R005 — `header_aware` chunking override without `required_anchors`

**Severity:** info
**Category:** RAG / pipeline completeness

## What this catches

A `[[document]]` entry that sets `chunking_override = "header_aware"`
but declares no `required_anchors`.

## Why it matters

Header-aware chunking works by splitting the document at heading
boundaries. The `required_anchors` list tells the chunker which
heading levels to honor (`["##"]` means H2 minimum, `["#", "##"]`
means H1 or H2, etc).

Without `required_anchors`, the chunker either falls back silently
(defeating the override) or produces nonsense (treating every line
that starts with `#` as a section break, including code fences and
comments). Both fail open in ways the indexer doesn't surface.

## Suggested fix

Add the anchor levels your source actually uses:

```toml
[[document]]
source = "docs/policies/**/*.md"
chunking_override = "header_aware"
required_anchors = ["##"]            # this source's policies start at H2
```

For multi-level heading structures (APIs that nest endpoints):

```toml
required_anchors = ["#", "##", "###"]
```

The list is a minimum, not a target — chunks may still split at
deeper levels naturally.

## When to silence

R005 is INFO. If you know the source has unambiguous headers at
every level and your chunker handles them, the explicit anchors
are documentation, not a hard requirement.
