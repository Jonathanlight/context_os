# P002 — Email address in title

**Severity:** warning
**Category:** Platform

## What this catches

A rule title containing an email address. The regex is intentionally
conservative — `name@domain.tld` style only.

Examples that fire:

- `Send build failures to ops@example.com`
- `Approval required from jonathan.kablan@example.com`
- `Ping security@acme.io before changing auth code`

## Why it matters

Email addresses in rule titles encode coupling to a specific person
or team. The text reads as a directive but the operationalization
depends on the person at that address still being around, still
owning the topic, and the LLM having any way to actually email them
(it usually doesn't).

The same content belongs in structured fields where downstream tools
can act on it — `author`, `links`, or a project-level `OWNERS` file —
not in the LLM-facing rule text.

## Suggested fix

Move the contact to the right structural field:

```toml
# Before (P002 fires):
[[rules]]
title = "Send build failures to ops@example.com"

# After:
[[rules]]
title = "Notify the ops team on every build failure"
links = ["mailto:ops@example.com"]
```

For rules that name an *owner*, prefer a team name or role over an
individual: `the platform team`, `the security on-call`, `the
@databases group`.

## When to silence

If the rule must literally contain the email address (e.g. a CC
template the LLM has to reproduce), wrap it in a code fence or move
it to `example_good`. The title itself should still describe the
behaviour.
