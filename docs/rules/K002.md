# K002 — Must-rule without rationale

**Severity:** warning
**Category:** Completeness

## What this catches

A rule with `severity = "must"` and no `rationale` field (or a rationale
that contains only whitespace).

Example that fires:

```toml
[[rules]]
id = "SEC-042"
title = "Sanitize all user-provided paths"
severity = "must"
# missing: rationale = "..."
```

## Why it matters

`must` is the strongest severity — the rule is absolute. When the LLM
encounters a `must` it has to weigh against another rule, the rationale
is what disambiguates. Without it, the model falls back to its
training distribution and the conflict resolution becomes unpredictable.

`should` and `may` rules carry implicit flexibility — they encode a
preference, not a guarantee — so K002 only fires on `must`.

## Suggested fix

Add a one-sentence rationale that names what breaks if the rule is
violated:

```toml
[[rules]]
id = "SEC-042"
title = "Sanitize all user-provided paths"
severity = "must"
rationale = "Prevents path-traversal attacks reading arbitrary files."
```

The rationale doesn't need to be long. The shortest useful rationale
names the failure mode (security incident, data loss, performance
regression, broken contract).

## When to silence

If the rule is genuinely self-evident — `Never commit secrets`, perhaps —
adding a rationale is still cheap and helps future readers. There is
almost no good reason to silence K002.
