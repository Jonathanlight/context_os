# S005 — Body H1 missing or mismatched

**Severity:** info
**Category:** Skill / body coherence

## What this catches

The body of a `SKILL.md` either has no `# H1`, or its H1 text does not
match the YAML `title` field. Comparison is case-insensitive and
tolerates bold / italic markdown markers.

The rule is silent on empty bodies (that's a structure problem, not a
heading one — and a different failure mode).

## Why it matters

Real-world Anthropic `SKILL.md` files almost universally lead the
body with `# <title>`. The H1 anchors the body as the skill's
documentation; the model uses it to confirm the right document was
loaded into context.

When the H1 is missing, the model has nothing in the body that names
the skill. When the H1 mismatches the YAML title, the metadata and
the prose drift — a sign that one of them was renamed without
updating the other.

## Suggested fix

Make the body open with an H1 matching the YAML title:

```yaml
---
name: pdf-extract
title: PDF invoice extraction
description: …
---

# PDF invoice extraction

When invoked, this skill …
```

Both atx (`# Title`) and setext-style headings count. Bold / italic
markers are stripped before comparison, so:

```markdown
# **PDF invoice extraction**
```

still matches `title: PDF invoice extraction`.

## When to silence

S005 is INFO so it never breaks CI. If your house style intentionally
omits the H1 (the body opens with a paragraph or a code fence), the
rule is noise — set it aside.
