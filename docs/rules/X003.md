# X003 — Question instead of directive

**Severity:** warning
**Category:** Anti-pattern

## What this catches

A rule title ending in `?`. Rules are directives — they tell the LLM
what to do or not do. Questions encode uncertainty and have no
enforceable shape.

Examples that fire:

- `Should we validate every input?`
- `Do we use camelCase or snake_case?`
- `What's the right timeout for HTTP clients?`

Trailing whitespace before the `?` is tolerated.

## Why it matters

A question in the rules section reads as a design decision the author
hasn't made. The LLM has no policy to apply; it has to guess. Worse,
the question often sits next to declarative rules and gets the same
weight, so the model treats "Should we validate every input?" as if
it were equivalent to "Validate every input." That's wrong — the
question doesn't say what to do when the answer is *no*.

## Suggested fix

Either commit to a decision and rewrite as a directive, or move the
question out of the rules section entirely:

| Question | Directive |
|---|---|
| `Should we validate every input?` | `Validate every input crossing a trust boundary` |
| `Do we use camelCase or snake_case?` | `Use snake_case for Python identifiers and camelCase in TypeScript` |
| `What's the right timeout for HTTP clients?` | `HTTP clients use a 5-second connect timeout and a 30-second read timeout` |

Open questions belong in an issue tracker, a design doc, or a `## Open
questions` prose section — not in `[[rules]]`.

## When to silence

Rare. If the title genuinely needs to end with a question mark — say,
the rule is `Ask "What changed?" before opening a PR` — wrap the inner
question in quotes so the title's final character is the closing quote,
not a `?`. That changes the surface text and gives X003 a clean signal.
