# R003 — Corpus has no `freshness_policy`

**Severity:** info
**Category:** RAG / pipeline completeness

## What this catches

A `[rag]` block with no `freshness_policy` field.

## Why it matters

Without a freshness policy, the indexer has nothing to compare
document age against, so stale content keeps surfacing forever.

For a documentation corpus where the docs reflect product behavior,
this is a real bug: the LLM cites stale information confidently and
the user can't tell. A freshness policy gives the indexer a clean
contract: "anything older than 30d is marked stale; the retrieval
layer can deprioritize or refuse."

## Suggested fix

Set a `freshness_policy` matching the corpus's update cadence:

```toml
[rag]
freshness_policy = "30d"   # docs older than 30 days marked stale
```

The compact format is `<integer><unit>` where unit is `d` / `w` / `m`
/ `y`. `1y` is fine for slow-moving corpora; `7d` for high-churn
operational runbooks.

## When to silence

R003 is INFO because some corpora are genuinely permanent — legal,
historical, reference material that doesn't decay. The rule is a
nudge, not a defect.
