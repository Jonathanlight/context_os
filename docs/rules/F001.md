# F001 — Excessive ALL CAPS

**Severity:** warning
**Category:** LLM-friendliness

## What this catches

A rule title where 70% or more of the alphabetic characters are uppercase,
and the title has at least 15 letters.

Examples that fire:

- `MUST USE TYPE HINTS ON EVERY PUBLIC FUNCTION`
- `NEVER COMMIT API KEYS OR DATABASE PASSWORDS`
- `ALWAYS VALIDATE INPUTS AT EVERY TRUST BOUNDARY`

Examples that **do not** fire (short or contain only acronyms):

- `USE HTTPS` — 8 letters, below the minimum
- `Use HTTPS and HTTP/2 for API endpoints` — only 11 of 30 letters uppercase

## Why it matters

ALL CAPS feels emphatic to humans but dilutes attention for the LLM:
every token is "important", so nothing is. Modern instruct-tuned models
treat case as signal — uniform uppercase erodes that signal across the
rule and the rules around it.

Repeated all-caps shouting also costs more tokens than the equivalent
sentence case (uppercase letters often tokenize less efficiently than
mixed case for the same content).

## Suggested fix

Use sentence case. Reserve ALL CAPS for well-known acronyms (`HTTPS`,
`JSON`, `API`, `OAuth2`, `URL`, `HTTP/2`, ...). Move emphasis to the
severity field (`must` / `should` / `may`) which the analyzer
understands, not to the typography.

| Shouting | Sentence case |
|---|---|
| MUST USE TYPE HINTS ON EVERY PUBLIC FUNCTION | Use type hints on every public function (severity: must) |
| NEVER COMMIT API KEYS | Never commit API keys (severity: must) |
| ALWAYS VALIDATE INPUTS | Validate every input crossing a trust boundary (severity: must) |

## Tuning

- Minimum length: 15 letters. Short titles like `USE HTTPS` are not flagged.
- Threshold: ≥ 70% uppercase among alphabetic characters.

Both numbers are constants in `src/contextos/analyzers/agent/llm_friendly.py`.
