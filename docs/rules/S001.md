# S001 — Description has no trigger phrasing

**Severity:** warning
**Category:** Skill / description quality

## What this catches

A `SKILL.md` whose `description` field never mentions *when* the model
should invoke the skill. ContextOS scans for any of these phrases
(case-insensitive):

- `when `
- `triggers`, `trigger ` (with trailing space — avoids matching `trigger_keywords`)
- `use this`, `use when`
- `invoke when`
- `asks to`, `asks for`
- `user requests`, `user wants`, `user needs`

If none appear, S001 fires.

## Why it matters

The description is the **only** string the model sees when deciding
whether to route a user prompt to this skill. A description like
`Extracts text from PDFs` documents capability but does not name the
trigger condition — so the model has no signal to fire, and the skill
sits dark.

The single biggest class of "skill never fires" bugs in production
shipping comes from descriptions that describe behavior without
describing the trigger.

## Suggested fix

Rewrite the description with a one-sentence behavior summary followed
by an explicit trigger clause:

```yaml
# Before — capability only
description: Extracts text and tables from PDF documents.

# After — capability + trigger
description: |
  Extracts text and tables from PDF documents. Triggers when the user
  uploads a `.pdf` file or asks to parse / extract content from a PDF.
```

## When to silence

If the description is loaded with synonyms or trigger language that
ContextOS doesn't recognize, extend the phrase list in
`src/contextos/analyzers/skill/description_quality.py` rather than
silencing the rule. S001 has WARNING severity precisely because the
default rule is "you almost always want a trigger phrase."
