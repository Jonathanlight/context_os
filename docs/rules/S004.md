# S004 — Skill has no `example_invocation`

**Severity:** info
**Category:** Skill / body coherence

## What this catches

A `SKILL.md` (or `[[skill]]` block in a `.ctx`) whose
`example_invocation` field is missing, `None`, or whitespace-only.

## Why it matters

Prose descriptions describe routing conditions abstractly:
"triggers when the user asks to extract PDF tables." An
`example_invocation` describes the same condition **concretely**:
`Extract the line items from this invoice.pdf`.

Concrete samples pin down the trigger far better than prose. They
also catch entire failure modes the description misses — e.g.
plurals (`extract` vs `extracts`), tenses, anchoring phrases. Skills
without an `example_invocation` routinely misfire on edge cases that
a one-line sample would have anchored.

## Suggested fix

Add the literal user prompt the skill expects to handle:

```yaml
example_invocation: Extract the line items from this invoice.pdf
```

```toml
# Or in a .ctx [[skill]] block
[[skill]]
name = "pdf-extract"
example_invocation = "Extract the line items from this invoice.pdf"
```

Pick the prompt you would write yourself if you were testing the
skill manually. That is the most honest trigger sample you have.

## When to silence

If the skill genuinely has no canonical invocation — for example, a
skill that wraps a tool the model calls programmatically rather than
in response to a user prompt — S004 is INFO, no action required.
