# A003 — Vague quantifier

**Severity:** warning
**Category:** Ambiguity

## What this catches

A rule title that hedges its scope with a fuzzy quantifier — a word that
gestures at frequency or proportion without naming a measurable threshold.

Examples that fire:

- `Rarely use shared mutable state`
- `Most public APIs need a docstring`
- `Sometimes prefer composition over inheritance`
- `Some database queries should run in a transaction`

## Trigger words

`usually`, `often`, `sometimes`, `rarely`, `frequently`, `occasionally`,
`most`, `few`, `many`, `several`, `some`, `a lot`, `lots of`, `plenty of`.

Match is whole-token, case-insensitive, with word boundaries on each
side. `summary` does not fire on `some`; `most public APIs` does.

## Why it matters

The model cannot enforce "rarely use X" because it has no count to
compare against. "Sometimes prefer composition" tells the model nothing
about *when* — leaving every decision to default behaviour. The rule
takes tokens without shaping output.

## Suggested fix

Replace the fuzzy quantifier with a measurable trigger or scope:

| Vague | Concrete |
|---|---|
| Rarely use shared mutable state | Use shared mutable state only behind an `asyncio.Lock` |
| Most public APIs need a docstring | Every public function in `src/` has a Google-style docstring |
| Sometimes prefer composition | When two classes share > 50% of their interface, extract a Protocol |
| Few imports per file | Module-level imports ≤ 15 per file |
| Some queries need a transaction | Writes to multiple tables require `with conn.transaction()` |

## When to silence

There is rarely a good reason to leave a fuzzy quantifier in a rule. If
the rule truly does not apply uniformly, name the discriminator: *which*
public APIs need a docstring, *when* the transaction is required.
