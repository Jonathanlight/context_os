# R004 — Corpus has no `embedding_model`

**Severity:** warning
**Category:** RAG / pipeline completeness

## What this catches

A `[rag]` block with no `embedding_model` field (or a whitespace-only
one).

## Why it matters

The indexer needs an embedding model name to know how to vectorize
the corpus. Two failure modes if you leave it unspecified:

- **Reproducibility break** — two indexers reading the same manifest
  may pick different defaults, producing two non-comparable indexes
  that swap silently depending on which environment runs.
- **Vendor lock-in by accident** — a default chosen by the indexer
  vendor pins you to their billing without an explicit choice on
  your end.

R004 is WARNING because the pipeline doesn't crash without an
`embedding_model` — the indexer falls back to something — but the
fallback is rarely the right call for production.

## Suggested fix

Declare the model explicitly:

```toml
[rag]
embedding_model = "voyage-3"        # Voyage AI — high quality, low cost
# embedding_model = "text-embedding-3-large"  # OpenAI
# embedding_model = "all-MiniLM-L6-v2"        # local, free
embedding_dimensions = 1024         # optional but recommended
```

ContextOS doesn't validate the model name against a registry —
that list churns and a typo here is recoverable. The point is to
**commit to a choice** in the manifest.

## When to silence

If your team has a global default in the indexer config and you
intentionally want the manifest to defer to it, you can suppress
R004 in audit's JSON output. But that's the kind of decision worth
making explicit in the file rather than implicit through omission.
